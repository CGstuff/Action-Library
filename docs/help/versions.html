Versions

Action Library never overwrites an animation. Capture over one and the old take is kept as a previous version. This page covers how that works and how to get an old version back.

How versioning works

Capture with the name of something already in the library and you're offered New Version. Take it, and:

  • the new capture becomes the latest,
  • the previous one is moved into version storage and kept,
  • both stay linked together as one animation's history.

Versions are numbered v001, v002 and so on. The library grid shows you the latest of each — you don't have to look at six versions of a jump while browsing.

Nothing is deleted by versioning. Every take you've ever captured is still on disk.

Looking at the history

Right-click a card and choose View Lineage — or press View History in the metadata panel. You get a table of every version of that animation, each with its own thumbnail, preview video, notes and annotations.

From there you can:

  • Play any version's preview.
  • Apply This Version — push an old version onto your rig without changing which one is the latest. Double-clicking a row does the same.
  • Set as Latest — promote an old version back to being the current one.
  • Compare — see below.
  • Read the review notes left on each version.

Set as Latest

Decided v002 was better than v003? Select it and press Set as Latest. The card in the library goes back to showing v002, and v003 stays in the history — you can flip back at any time. Nothing is lost either way.

Comparing two versions

Select two rows in the history and press Compare. Their previews play side by side, in sync, with each version's review notes and annotations alongside. It's the fastest way to see what actually changed between takes — and the honest way to check whether the note got addressed.

Where versions live

Your library keeps the latest version of each animation in the main folder, and older versions in a _versions folder alongside it. That's why browsing is quick: the app isn't wading through history to show you your library.

You don't need to touch these folders, but it's worth knowing they're there — if you back up your library folder, you're backing up every version too.

Deleting a version

Delete the latest version of something and Action Library promotes the next newest automatically, so the animation stays in your library — just one take older. Deleting doesn't leave you with a gap in the grid where an animation used to be.

See Archive & delete for what deleting involves.

Working with versions

  • Use the same name deliberately. Same name = version. Different name = different animation. That's the whole rule.
  • Don't put version numbers in your names by hand. Action Library adds and tracks them. A name like jump_v2_final_FIXED fights the system that already does this for you.
  • Notes are per version. A note on v002 stays with v002, so feedback doesn't drift onto a take it wasn't about.
