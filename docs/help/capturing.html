Capturing

Getting animation out of Blender and into your library. Everything here happens in Blender, in the 3D Viewport sidebar (N) under the Animation tab.

What a capture actually saves

Each capture creates a self-contained folder in your library holding:

  • a .blend with the action data,
  • a .png thumbnail, rendered from your viewport,
  • a .webm preview video (actions only — poses are one frame),
  • a .json of metadata: name, rig type, frame range, author, tags.

Blender then drops a note for the desktop app, which picks it up within a few seconds and adds the card. Nothing else is required of you.

The thumbnail and preview are rendered from your viewport, so what you see is what you get. Frame the shot before you capture — a clear side-on view of the motion beats a three-quarter view of the character's back six months from now.

Capturing an animation

  1. Select the armature.
  2. Open the Capture panel.
  3. Enter a name.
  4. Set the frame range.
  5. Press Capture Action.

Naming

The name is how you'll find it again, and it decides the folder on disk. Descriptive beats clever: jump_heavy_land is findable, Action.003 is not. If your studio uses a naming template, the panel gives you fields to fill instead of a free-text box, and builds the name from them — see naming settings.

Search covers names, tags, descriptions and rig type — so names don't have to carry everything. Name it for the motion, tag it for the context.

Capturing a pose

Capture Pose saves the current frame as a single-frame pose. It lands in the Poses side of the library and gets a thumbnail but no preview video. Poses are what pose blending works on — see Pose blending.

Selected bones only

Tick Selected Bones Only and the pose records just the bones you have selected. Good for a hand shape or a facial expression you want to drop onto a character without touching the rest of the rig.

Capturing part of an animation

Capture Selected takes the keyframes you have selected in the dope sheet and makes a new animation from them, shifted to start at frame 1. Use it to lift one good section out of a long take without cutting up the original.

Capturing over something that exists

Capture using the name of something already in the library — or re-capture an animation you originally applied from the library — and Action Library asks what you mean:

  • New Version — this is an improved take of the same animation. The previous one is kept and this becomes the latest.
  • New Animation — this is a different thing that happens to have a similar name. Both are kept, independently.

Choose New Version and the older files are moved aside into version storage rather than deleted. Nothing is ever overwritten — see Versions.

This is the intended way to iterate: capture, apply, improve, capture again with the same name. You get a history for free, and the card in the library always shows your latest.

Updating a preview

If the thumbnail or preview came out badly — wrong angle, character out of frame — you don't have to re-capture. Frame the viewport how you want it, select the animation, and press Update Preview. It re-renders the thumbnail and video for the existing animation and leaves the animation data alone.

Update Preview works on actions, not poses.

When a capture doesn't appear

  • Give it five seconds. The app polls on a short timer.
  • Press refresh in the app's header.
  • Check both sides agree on the library. The addon panel shows the library path it's using; it should match Settings › Storage Locations in the app.
  • Check the armature was selected when you pressed capture.
  • Still nothing? The console button in the app's header shows what it recorded. See install troubleshooting.
