Archive & delete

Getting rid of things — and getting them back. How this behaves depends on which mode you're in, so start there.

In Solo mode, delete means delete. The folder is removed from disk, including every version of that animation. There is no Trash to fish it back out of.

The Studio mode pipeline

Studio mode gives you two stages before anything is really gone:

Library → Archive → Trash → gone

Archive

Select what you want gone and press the archive button in the header (or use the card's right-click menu). The animation leaves the library and appears in the Archive folder. It's still on disk, whole, and can be restored.

Archive is for "I don't want to see this while I work" rather than "destroy it".

Restore from Archive

Select the Archive folder, select what you want back, and press Restore to Library in the bulk toolbar. It returns with its metadata.

Trash

In the Archive view, deleting again moves the item on to Trash — the last stop before it's gone for good. Trash can still be restored (back to Archive), though some metadata may not survive the round trip.

Emptying

Right-click the Archive folder for Empty Archive, which moves everything in it to Trash. Right-click Trash for Empty Trash, which permanently deletes it all.

Empty Trash is the point of no return. Everything in it is removed from disk.

The permanent-deletion guard

Permanent deletion is gated by a setting — Allow permanent deletion, under Settings › Storage Locations. It's off by default, and while it's off, Action Library refuses to destroy anything. If Empty Trash doesn't seem to do anything, that's why.

Deleting and versions

Removing an animation removes all of its versions — the whole history goes with it.

But delete the latest version specifically and Action Library promotes the next newest to take its place, so the animation stays in your library one take older, rather than vanishing. See Versions.

What this looks like on disk

Archive and Trash are real hidden folders inside your library (.deleted and .trash). Archiving moves the animation's folder into them, whole. So an archived animation is still a normal folder of normal files — if the app ever failed you, you could find it yourself with a file browser.

Because Archive and Trash live inside the library, they take up space until you empty them, and they travel with the library if you copy it.

Which mode should you use?

If more than one person touches the library, Studio mode. The cost of a wrong delete on a shared library isn't your afternoon, it's someone else's.

Working alone with a library you back up? Solo mode is less ceremony — but "I back it up" should be true, not aspirational.
