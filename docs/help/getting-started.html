Getting started

New to Action Library? Start here. This page covers what it is, the handful of concepts worth knowing, what happens the first time you launch it, and an end-to-end run through capturing an animation and applying it to another rig.

What Action Library is

Action Library is a place to keep your animations and poses so you can find them again and reuse them — across scenes, across projects, across rigs. Instead of digging through old .blend files trying to remember which one had the good jump, you capture it once and it's in your library forever.

Two halves

It comes as two pieces that work together:

  • The desktop app — the browser. Thumbnails, folders, search, tags, versions, notes. This is where you look at things.
  • The Blender addon — the hands. It captures animation out of Blender into the library, and applies animation from the library back onto a rig.

You install the addon from inside the app — see Install & update. The two talk to each other automatically over a local connection, so a capture in Blender shows up in the app within a few seconds without you doing anything.

Where your animations live

Everything lives in one folder you choose: the storage folder, or library. Inside it, each animation gets its own folder holding a .blend file with the animation data, a thumbnail, a preview video, and a small .json file of metadata. Alongside those sits a database the app uses as its index.

Two things follow from that, and they're worth knowing up front:

  • Your animations are plain files on disk. Nothing is locked inside a proprietary format, and you can back the folder up by copying it.
  • If the folder is on a shared drive, everyone pointed at it sees the same library. That's how a small team shares animations.

Key concepts

TermWhat it means
LibraryThe storage folder holding all your animations. You can have more than one and switch between them.
ActionAn animation over multiple frames — a walk, a jump, a take.
PoseA single frame. Captured and applied the same way; kept separate because you use them differently.
VersionCapture over an existing name and the old one is kept as a previous version rather than being lost. The newest is the "latest".
Rig typeA label for which rig an animation was made for, so you can filter to the ones that'll actually fit.
TagA free-form label. Tags also drive folders — see a note on folders below.

Actions and poses

The split is just frame count: capture a single frame and it's a pose, capture a range and it's an action. They're stored in separate folders (actions/ and poses/) and the folder tree gives each its own view, so a library full of poses doesn't bury your animations.

First run

The first time you launch Action Library it asks you two things.

Where to keep your library

Pick an empty folder, or one you've used before. An empty folder becomes a new, empty library — the app creates everything it needs inside it. Put it somewhere you'd be happy backing up. If you work with other people, put it on the shared drive and point everyone at the same path.

You can change this later, and you can keep several libraries and switch between them — see the library picker at the top-left of the window.

Who you are

Action Library then asks for a name. This is only used to attribute review notes and drawings, so your colleagues know who wrote what. It's stored on your machine, not in the library — which means everyone pointed at a shared library keeps their own identity, and nobody overwrites anyone else's.

The interface

The window is three panels, left to right.

Folder tree (left)

Your way around the library:

  • Home — everything.
  • Actions / Poses — split by type.
  • Recent — what you've looked at lately, on this machine.
  • Favorites — anything you've starred.
  • Your folders — the ones you make.
  • Archive / Trash — things you've put aside or deleted.

Cards (middle)

Your animations, as thumbnails. Click one to select it — its preview video plays in the panel on the right. Double-click to apply it to your rig in Blender. The slider in the header changes the card size, and there's a grid/list toggle next to it.

An animation can live in several folders at once — a run belongs in Locomotion and GameDev and Show01 together. Dragging a card into a folder adds it there and leaves it wherever else it is, and nothing moves on disk.

Metadata and apply (right)

Details of whatever's selected — name, description, rig type, tags, status, and a video preview. Underneath is the Apply panel, with the options used when you send it to Blender.

Header

Left to right: the library picker (which library you're in), new folder, search, filters, sort, the view controls, and refresh. On the right: archive/delete, your identity, and the about, console, shortcuts and settings buttons.

Press H for the keyboard shortcuts overlay, and F1 for this documentation.

Quick start

End to end: get an animation in, then get it back out onto a different rig. Assumes the addon is installed — if not, do that first.

1. Capture an animation

  1. In Blender, open a scene with an animated rig.
  2. Select the armature.
  3. In the 3D Viewport press N, choose the Animation tab, and find the Capture panel.
  4. Give it a name — something you'd search for later. jump_heavy beats Action.003.
  5. Set the frame range you want.
  6. Press Capture.

Blender writes the animation, renders a thumbnail and a preview, and tells the app. Within a few seconds a new card appears in your library. If it doesn't, hit refresh in the header.

2. Find it again

Type part of the name in the search box, or narrow down with the rig-type and tag filters. Select the card and the right-hand panel fills in — give it a description and a couple of tags now, while you still remember what it was for. Future you will be grateful.

3. Apply it to a rig

  1. In Blender, select the armature you want to animate.
  2. In Action Library, double-click the card.

The animation lands on your rig. Hold a modifier while you double-click to change what happens:

HoldEffect
CtrlMirror it left-to-right.
ShiftUse action slots (Blender 4.4+).
AltInsert at the playhead instead of replacing the action.

The Apply panel on the right has the same options as checkboxes, if you'd rather see them than remember them.

4. Capture a new version

Improved it? Capture again with the same name. Action Library keeps the old one as a previous version instead of overwriting it — the card shows the newest, and the older ones are a right-click away under version history, where you can look at any of them or promote one back to being the latest.

That's the loop: capture, name it well, apply, capture again when it improves. Everything else in Action Library exists to help you find the thing you captured six months ago.
